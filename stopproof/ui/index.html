Prove your AI agent actually stopped.

When an AI agent is cancelled, top-level loops report OK — yet asynchronous workers often keep draining job queues and fire irreversible side effects like sending unauthorized emails or charging accounts. StopProof maps the repository, locks a deterministic race test inside isolated Nebius microVMs, repairs the worker with Nemotron, and computes mathematical proof with a deterministic verifier — never the model.

    How to verify it yourself

    1. Compare live behavior first.Press Compare all 3 agents above. All three pass their own conventional unit test suite (3/3 pass), yet vulnerable_agent delivers 4 outbound emails after STOP while fixed_agent blocks them and opaque_agent is flagged CANNOT ESTABLISH.
    2. Run sandboxed verification & auto-repair.Select vulnerable_agent in the left sidebar and press Run verification. Nemotron maps the handoff, locks a race test by sha256, reproduces the bug in a Nebius microVM, patches the worker/queue, and re-runs the identical locked test.
    3. Inspect the timeline and diff.Switch between Baseline and After patch tabs to see the exact event ordering relative to the red STOP requested boundary and the unified diff applied to the worker.
    4. Recompute every verdict from raw events.Press Re-run integrity checks under Evidence (or run python -m stopproof verify-bundle runs/<run_id>) to recompute all 18 window verdicts and sha256 hashes independently.
    5. Try to fool the verifier.Switch to Technical details, open Edit this trace and re-verify, and delete a worker_blocked event: the verifier immediately returns CANNOT ESTABLISH.
